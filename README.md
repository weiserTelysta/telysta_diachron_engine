# TelystaLexisEngine

**Neuro-Symbolic Conlang Evolution Engine**

## 1. 项目愿景和概述

本项目旨在开发一个高度自动化、专业且具创造性的架空语言生成与演化系统。本引擎摒弃传统的“查表式”或“纯随机”造语方案，采用前沿的**神经符号混合架构（Neuro-Symbolic Architecture）**：

- **符号层（核心基座）：** 依托 Python 严密的算法与数据结构，负责不可逆的历时语音演变、词类系统（POS）以及形态学演化的结构化计算。包含：历史音系演变正则引擎、基于齐夫定律（Zipf's Law）的语用频率矩阵、以及确定的基础句法生成器。
    
- **神经层（上层渲染）：** 依托大语言模型（LLM），在严格的符号规则计算完毕后，基于确定性结构生成时代纪事、解释语义漂移、润色文化隐喻，并为语言演化的“异常突变”提供合理化叙事。
    

最终产物将不仅是一本静态字典，而是一个具备动态历史脉络、独立语法形态、支持自然语音导出与句法级翻译的世界观语言学基座。

## 2. 最小可运行版本 (MVP - Phase 0)

为避免过度设计导致项目停滞，开发第一阶段将严格限制边界，优先打通最小系统闭环：

- **输入：** 全局常量 `MY_WORLD_SEED` 与 100 个斯瓦迪士核心概念。
    
- **输出：** Era 0（原始语）到 Era 2（演化语）的 100 个核心词汇快照，以及 10 个符合基础语序（如 SOV）的测试句。
    
- **包含模块：**
    
    - 基础音系生成（CV/CVC 音节拼接）。
        
    - 词类标签系统（Noun, Verb 极简分类）。
        
    - 2-3 条硬编码的音变规则（如：词尾元音脱落、清辅音浊化）。
        
    - 无 LLM 参与的纯净测试环境。

## 3. 系统解耦架构设计

系统采用严格的领域驱动设计（DDD），将业务逻辑与基础设施彻底分离：

### 3.1 领域模型层 (Domain Layer)

- **词汇实体 (Lexical Entity)：** 定义词汇的 JSON/DataClass 标准结构，必须包含 `id`, `pos` (词类), `ipa_current`, `ipa_history` (数组), `frequency_weight` 等关键字段。
    
- **语义与配价系统 (Semantics & Valency)：** 初期采用极简的行为逻辑原语（如 `EAT(agent, object)`），取代复杂的全量语义网，确保动词配价可计算。
    
- **类型学参数矩阵：** 确立语序基因（SVO/SOV 等）与形态演化方向（孤立语/黏着语/屈折语）。
    

### 3.2 核心引擎层 (Engine Layer)

- **历时音变解析器：** 引擎读取 YAML/JSON 格式的音变规则（包含触发环境和优先级），使用 Python `re` 模块执行顺序演变计算。
    
- **齐夫频率函数：** 明确定义衰减函数 $Erosion\_Rate = f(Frequency)$。高频词触发深度脱落，低频词保持相对完整。
    
- **冲突消解中心：** 当两条规则同等触发或产生非法音节时，依据预设权重或回滚机制处理。
    

### 3.3 基础设施层 (Infrastructure Layer)

- **开发环境：** 采用 `Poetry` 进行依赖锁定，保障多端结果一致。
    
- **数据存储：** 敏捷期采用结构化 JSON 管理快照；后期引入 Neo4j 图数据库，将演化路径作为边，支撑词源学（Etymology）追溯。
    

### 3.4 表现与接口层 (Presentation Layer)

- **发音与正字法 (G2P)：** 分离底层 IPA 与表面拼写。后端仅计算 IPA，前端映射奇幻正字法（如 /θ/ -> `th`）。接入 Edge-TTS 或 eSpeak NG 提供音频支持。
    
- **维基展示：** 使用 Streamlit 构建带有时光轴拖拽、发音按钮与演化树可视化的仪表盘。

## 4. 核心推演管线 (Evolutionary Pipeline)

引擎的运转遵循历史时间轴，分为四个核心生命周期：

### 阶段一：时代大爆炸 (Genesis)

1. **音系与初始词库：** 结合随机数种子与音素权重（如偏好流音以获得柔和听感），生成初代核心词根，并严格打上 POS（词性）标签。
    
2. **设定语法基因：** 确立初始语序与时态倾向（例如，强制动词屈折变化，或使用独立助词）。
    

### 阶段二：物理磨损与规则演化 (Erosion & Evolution)

1. **加权音变：** 按照时代步进执行历史语言学规则（同化、弱化、脱落等）。
    
2. **同音词灾自动化处理：** 当同音词溢出阈值（`homophones > threshold`），**符号规则**自动触发词缀补偿或双音节化。LLM 仅在事后负责生成“为何添加该词缀”的叙事解释，绝不干预计算。
    
3. **不规则伤疤生成：** 基于齐夫矩阵，锁定极高频词（如 “我”、“是”），阻断其参与标准规则化，产生历史遗留的不规则变位。
    

### 阶段三：语法化与句法漂移 (Grammaticalization)

1. **虚词降级：** 模拟真实语言演变。高频实词因读音极度磨损，降级为语法标志（如：动词“去” -> 助词“将” -> 将来时前缀 `ga-`）。
    
2. **句法级翻译与 AST 组装：** 解析用户的基本逻辑输入，结合当前时代的 POS 系统、不规则表与存活词汇，输出符合该时代语境的句子。
    

### 阶段四：文化渲染与纪事 (LLM Lore Generation)

- **数据交接：** 引擎将本时代的存活词表、规则突变快照以强 JSON Schema 格式传递给 LLM。
    
- **神话包装：** LLM 仅负责“看图说话”，生成 100 字左右的时代纪事，将枯燥的语法变迁包装为人口迁徙、技术变革或文化神话。

## 5. 特色工程学与安全机制

1. **软删除与化石词根 (Soft Delete)：** 演化淘汰的词汇禁用硬删除，打上 `"is_dead": true` 标签。该词在现代词典中隐藏，但其残留音节可作为“化石前缀”存活于复合词中。
    
2. **单点热更新 (Hot Injection)：** 支持在特定时代强行注入借词（如 `"source": "古精灵语"`）。借词仅从注入点开始参与后续磨损，无需回滚前期数据，极大节省算力。
    
3. **逆向附会引擎 (Reverse Engineering)：** 为用户强行预设的现代词汇提供词源倒推。引擎寻找发音相近的古词，唤醒 LLM 强行“附会”合理解释。若逻辑断裂，系统将执行安全回滚。
    
4. **测试驱动的语言学 (TDD for Linguistics)：** 核心音变引擎配备完整的单元测试 (`tests/`)。每新增一条演化规则，必须通过基准词汇的预期演化校验，防止规则污染导致语言系统崩溃。
